ListUp

초대 코드로 참여하는 자가 호스팅 파일 공유 · 협업 도구

내 PC에 서버를 열고, 초대 코드 하나로 친구를 불러 파일을 나눕니다. 남의 파일을 고치고 싶으면 변경 제안을 올리고, 편집자가 확인한 뒤 반영합니다 — git의 협업 방식(제안 → 리뷰 → 병합)을 코드가 아닌 파일에 가져왔습니다.

최신 릴리즈 받기 Windows · Android 소스 코드

무료 · 오픈 소스(AGPL-3.0) · 외부 서비스 없이 내 서버 하나로 · PC 앱 · 안드로이드 앱 · 브라우저

하는 일

  • 저장소와 초대 코드

    저장소를 만들고 초대 링크(또는 코드)를 건넵니다. 권한 · 기간 · 인원을 정할 수 있고, 옆 사람은 QR 코드를 폰 카메라로 찍으면 됩니다.

  • 변경 제안 · 리뷰 · 병합

    열람 권한만 있어도 제안을 올릴 수 있고, 저장소는 편집자가 확인해 병합하기 전까지 바뀌지 않습니다. 내 제안의 반영 · 의견은 '내 제안'에서 모아 봅니다.

  • 변경 이력 · 되돌리기

    올리고 병합할 때마다 스냅샷이 남습니다. 실수로 덮어썼으면 이력에서 이전 시점의 파일을 그대로 받거나 되돌립니다.

  • 큰 파일 나눠 올리기 · 이어 올리기

    한 파일 2GB까지. 조각으로 나눠 올려 진행률이 보이고, 끊기면 다시 붙어 이어서 올립니다. 폴더째 올려도 구조가 남고, 폴더는 zip 하나로 받습니다.

  • 내 폴더와 비교

    기기의 폴더를 골라 저장소와 파일 이름으로 견줍니다. 저장소에만 있는 것은 골라 받고, 내 폴더에만 있는 것은 골라 올립니다. PC 폴더를 계속 맞춰 나가는 동기화 스크립트도 있습니다.

  • PC 앱에서 바로 서버 열기

    Windows 앱의 '이 PC에서 서버 열기 → 서버 켜기'면 끝. Node 설치 없이 밖에서 들어오기(Tailscale Funnel · Cloudflare 빠른 터널) · 백업 · 비밀번호 재설정까지 앱에서 합니다.

  • 열람파일을 보고 내려받고, 변경 제안을 올립니다.
  • 편집파일을 직접 올리고 지우고, 남의 제안을 병합합니다.
  • 소유자저장소 설정과 멤버를 관리합니다.

설치

설치 파일은 모두 GitHub의 최신 릴리즈에 있습니다. 새 버전이 나오면 앱이 알려 줍니다.

  • PC (Windows) listup-<버전>-windows-setup.exe를 받아 실행합니다. 코드 서명을 하지 않아 'PC 보호' 경고가 뜨면 '추가 정보 → 실행'. 켠 뒤 '서버 추가'로 받은 서버 주소를 넣고, 서버를 직접 열려면 '이 PC에서 서버 열기'.
  • Android listup-<버전>-android.apk를 폰에서 받아 설치합니다. '출처를 알 수 없는 앱' 설치를 허용해야 합니다. 서버 목록에서 서버를 추가하거나, 받은 초대 링크를 열면 됩니다.
  • 서버 직접 운영 리눅스 · 맥이나 터미널이 편하면 listup-<버전>.zip을 풀고 npm install → npm run serve -- --tunnel. 자세한 설정은 README '실행하기'.
최신 릴리즈 받기 모든 릴리즈

실행 기록(텔레메트리) 안내

앱을 같이 써 주는 친구들께 — 어떤 환경에서 앱이 느려지거나 오류가 나는지 알아보려고, 앱이 실행될 때마다 간단한 성능 기록을 내 기기 안에만 남깁니다. 학교 데이터 분석 과제용이고, 처음 켤 때 동의를 물으며 동의하지 않으면 아무것도 남기지 않습니다. 이름 · 파일 · 주소 같은 개인 정보는 모으지 않습니다.

왜 모으나요? 실행 한 번이 표의 한 줄이 되고, 모은 기록(300줄쯤)으로 어떤 기기 · 환경에서 오류가 몰리는지 묶어(군집 분석) 봅니다.

기록은 서버나 다른 곳으로 저절로 보내지 않습니다. 내가 직접 내보내 건네줄 때만 밖으로 나갑니다.

기록하는 항목 — 실행 한 번 = 한 줄, 12칸
칸 이름뜻
session_id이번 실행에 매긴 무작위 번호. 같은 기록이 두 번 합쳐지지 않게 할 때만 씁니다.
device_id앱이 처음 켜질 때 만든 무작위 기기 번호. 하드웨어 정보와 무관합니다.
date실행한 날짜(YYYY-MM-DD). 시각은 남기지 않습니다.
app_version앱 버전(예: 1.10.0).
device_class기기 분류 네 가지 중 하나 — 아래 기준.
os운영체제와 버전(예: Windows 11, Android 14).
avg_fps화면이 1초에 평균 몇 번 그려졌는지. 잴 수 없는 환경이면 빈칸.
min_fps_1s가장 버벅였던 1초 동안 그려진 횟수. 잴 수 없으면 빈칸.
max_ram_mb앱이 쓴 메모리의 최댓값(MB). 잴 수 없으면 빈칸.
duration_min앱을 켜 둔 시간(분).
error_count그동안 난 오류의 개수. 내용은 남기지 않고 개수만.
crashed앱이 비정상으로 꺼졌으면 1, 아니면 0.

오류는 개수 말고도 종류 이름별 횟수만 따로 …-errors.csv(칸: session_id, error_type, count)에 담길 수 있습니다. 오류 메시지 원문은 담지 않습니다.

기기 분류 기준 (device_class)

  • PC-고사양 — 논리 코어 8개 이상이면서 RAM 16GB 이상. 그 밖의 PC는 PC-저사양.
  • 모바일-고급형 — RAM 6GB 이상이면서 코어 8개 이상. 그 밖의 폰은 모바일-보급형.

브라우저는 RAM을 최대 8GB까지만 알려 주므로, 8GB로 나오면 가장 높은 칸으로 칩니다.

모으지 않는 것

  • 사용자 이름 · 아이디(이메일)
  • 파일 이름 · 경로
  • IP 주소
  • 입력한 내용 · 화면에 보이는 내용
  • 오류 메시지 원문
  • 하드웨어 고유 번호 · MAC 주소

끄기 · 지우기

기록은 앱 안에만 쌓이고 네트워크로 보내지 않습니다. 앱의 '실행 기록' 화면에서 언제든 모은 내용을 보고, 기록을 끄거나 전부 지울 수 있습니다.

내보내서 보내기

'실행 기록' 화면 → 기록 내보내기.

  • PC 앱 — 저장 창이 뜹니다. 기본 이름은 telemetry-YYYY-MM-DD.csv, 오류 종류는 옆에 …-errors.csv로 함께 저장됩니다.
  • Android — 공유 창이 뜹니다. 메신저나 메일로 바로 보내면 됩니다.
  • 브라우저 — 내려받기 폴더로 받아집니다.

받은 파일을 과제 담당에게 전해 주세요. 평범한 표(CSV)라 보내기 전에 열어 확인해도 됩니다.
